SmoreFit.AbstractGate — Type
AbstractGate

A gate decides, before any threshold is applied, which CM paramsets may count at all. A CM paramset that fails the gate is treated as score 0 and is never accepted.

A posterior has one gate. It is chosen in buildPosterior (gate = ...), stored as post.gate, and used by everything that reads the posterior afterwards. applyGate reports what it did.

Built-in gates: NullGate (no gating, the default) and IdentifiabilityMatchGate.

Adding a gate

Subtype AbstractGate and add a method of the (unexported) function

SmoreFit.gateScores(gate::MyGate, scores, uq_results, data_profiles) -> NamedTuple

that returns at least scores (the scores with 0 where a CM paramset fails, Vector{Float64}) and pass (a BitVector). scores holds one bridge score per CM paramset, uq_results the CM paramsets' profile results in the same order, and `dataprofilesthe data's profile result. To support interior queries ([posteriorScore](@ref), [inPosterior`](@ref)) also add

SmoreFit.gateInterior(gate::MyGate, score, lb, ub, post) -> Float64

which gates the score of one interior CM point from its interpolated SM-parameter box [lb, ub]. Without it, interior queries on a posterior built with that gate throw an ArgumentError.

SmoreFit.CMPosteriorResult — Type
CMPosteriorResult

Result of buildPosterior: which CM param_sets are consistent with the real-world data, scored by the chosen bridge method.

Both a hard accept/reject set (accepted) and the continuous scores are always stored, together with which CM paramsets pass the gate (`gatepass); which view to use is a choice made at read time via [posteriorSamples](@ref) (accept/reject) or [posteriorWeights](@ref) (graded). Becausecm_sampleis retained (with its gridaxesfor aGridCMSample), acceptance and scores can be reshaped back onto the CM grid via [acceptedGrid](@ref) / [scoreGrid`](@ref).

For grid-aware results, the per-cmparamset SM-parameter CI tables (lb_table, ub_table) and a prebuilt CM-grid bounds interpolator (get_bounds) are stored so that interior CM points (not among the cmparamsets) can be queried via inPosterior and posteriorScore. The full uq_results are also retained for inspection and any future re-analysis.

The result also records what built it: the data-side problem (data_problem), both sides' profile settings (data_profiles.method and each uq_results[i].method), the bridge settings (bridge, box_score, gate, min_score) and the interpolation method (interp).

Fields

  • cm_sample — CM parameter points (AbstractCMSample), row-aligned with accepted/scores/gate_pass
  • cm_names — CM parameter names (defaults from cm_sample.names; override via buildPosterior's cm_names kwarg)
  • accepted — BitVector; true where the cmparamset passes the gate and its score exceeds min_score: gate_pass .& (scores .> min_score)
  • scores — the bridge's consistency score per cmparamset, in [0, 1]. A cmparamset that fails the gate is treated as score 0 wherever a score is used (scoreGrid, posteriorWeights, accepted, the elbow); gate_pass says which ones those are
  • bridge — the bridge method used (:box_overlap, :data_trace_in_box, :symmetric_trace)
  • min_score — threshold used for accepted; default for interior queries. When buildPosterior was called with min_score = :elbow, this is the resulting τ_elbow
  • data_problem — the SMFitProblem (sm, real data, SM prior, loss) that the SM was fitted and profiled against on the data side; for the (sm, data, …) methods, the problem they build internally
  • data_profiles — the SM profile likelihood computed against the real data. Its method field holds the data-side profile settings (buildPosterior's profile_options), and data_profiles.fit_result.initial_parameters is the data fit's starting point (p0)
  • uq_results — the CM paramsets' profiles, one per row of `cmsample.params. Eachuq_results[i].method` holds the CM-side profile settings it was computed with
  • lb_table, ub_table — [n_cm_param_sets × n_sm_params] per-cmparamset SM-parameter CI lower/upper bounds derived from uq_results (with nothing falling back to the edge of the prior range, matching the :box_overlap bridge)
  • interp — the AbstractCIInterpolator used to build get_bounds (stored for every layout)
  • get_bounds — callable θ_cm -> (lb, ub) interpolating the CI tables across the CM grid (a SmoreBase.CIBoundsInterpolant); nothing for non-grid layouts. It can be rebuilt from the stored fields: SmoreBase._buildBoundsInterpolant(post.cm_sample, post.lb_table, post.ub_table, post.interp)
  • box_score — how the :box_overlap bridge scores box overlap, as passed to buildPosterior: :jaccard (overlap volume ÷ union volume; the default) or :data_normalized (overlap volume ÷ data-box volume). Interior queries reuse it, so they reproduce the stored scores. Recorded for every bridge but only consulted by :box_overlap.
  • gate — the AbstractGate of this posterior (NullGate when none was asked for). It is chosen once, in buildPosterior; interior queries (posteriorScore, inPosterior) and applyGate use it
  • gate_pass — BitVector; true where the cmparamset passes gate (all true under NullGate)

The interpolator and the gate are type parameters: CMPosteriorResult{I,G} with I <: AbstractCIInterpolator and G <: AbstractGate.

The data-side SM-parameter box and trace that the bridges compared against are not stored; they are SmoreFit._profileBox(post.data_profiles) and SmoreFit._profileTrace(post.data_profiles).

See also

posteriorSamples, posteriorWeights, acceptedGrid, scoreGrid, inPosterior, posteriorScore.

SmoreFit.IdentifiabilityMatchGate — Type
IdentifiabilityMatchGate()

The identifiability gate. Each side of each SM parameter's confidence interval is either bounded or open (see openSides). A CM paramset passes if, on every side of every SM parameter, its CI has the same shape as the data's CI: bounded where the data's is bounded, open where the data's is open. A CM paramset that fails counts as score 0.

The gate uses only the CI shapes, never the scores, so it is the same for every bridge.

At an interior CM point the CI shape is read off the interpolated box: a side is open if the interpolated bound sits at the edge of the profile range, and bounded if it lies strictly inside.

The profile range of an SM parameter is the range its profile covers:

  • normally, the SM prior range;
  • if the profiles were run with ProfileLikelihood(bounds = ...), that range instead. SmoreBase needs bounds when the prior is unbounded (for example a Normal), because a profile needs a finite range; bounds can also narrow a finite prior range.

SmoreFit.applyGate — Method
applyGate(post::CMPosteriorResult) -> NamedTuple
applyGate(gate::AbstractGate, post::CMPosteriorResult) -> NamedTuple

What the gate does to a posterior's scores.

applyGate(post) uses the posterior's own gate, post.gate: the one chosen in buildPosterior and already reflected in post.gate_pass, post.accepted, scoreGrid and posteriorWeights. Call it to see the gate's result in full.

applyGate(gate, post) is the special case: it evaluates a different gate on the same scores, to compare gates. It returns a result and leaves post (and post.gate) unchanged; to build a posterior with another gate, call buildPosterior again.

Returns

A named tuple with

  • scores — one score per CM param_set, 0 where it fails the gate (Vector{Float64})
  • pass — BitVector, true where the CM param_set passes

and, for IdentifiabilityMatchGate,

  • mismatch — BitArray, [n_cm_param_sets × n_sm_params × 2]: mismatch[i, j, 1] is true when CM paramset i differs from the data on the lower side of SM parameter j, and mismatch[i, j, 2] on the upper side (the layout of openSides, one slice per CM paramset)

Example

post = buildPosterior(sm, data, uq_results, cm_params; gate = IdentifiabilityMatchGate())
g    = applyGate(post)
count(.!g.pass)                   # how many CM param_sets fail the gate
dropdims(count(g.mismatch; dims = 1); dims = 1)   # failures per SM parameter (rows) and side (columns)
post.scores[post.gate_pass]   # the scores of the CM param_sets that pass

applyGate(NullGate(), post).pass  # what another gate would do: here, everything passes

SmoreFit.buildPosterior — Method
buildPosterior(problem::SMFitProblem, uq_results, cm_sample; kwargs...) -> CMPosteriorResult
buildPosterior(problem::SMFitProblem, uq_results, cm_params::AbstractMatrix; kwargs...)
buildPosterior(sm, data, uq_results, cm_sample; loss=GaussianNLL(), kwargs...)
buildPosterior(sm, data, uq_results, cm_params::AbstractMatrix; loss=GaussianNLL(), kwargs...)

Infer which CM parameter sets are consistent with real-world data, given the surrogate model and its per-cmparamset profile likelihood UQ from SmoreBase.

Two streams of profile information are combined:

  1. CM-side, already done — uq_results[i] is the SM's profile likelihood against the CM cmparamset at row i of cm_sample.params. These were produced upstream (e.g. by SmoreBase's quantifyUncertainty over all the CM param_sets) and are passed in unchanged.
  2. Data-side, computed here — the SM is fit and then profiled against the real observations. The ingredients for that fit-and-profile step are what problem (or the (sm, data, loss) triple, with sm_prior taken from uq_results[1].fit_result.prior) describe — not anything about the CM paramsets, which are fully captured by `uqresults`.

Each cmparamset is then scored by how well its SM-parameter confidence region (from uq_results[i]) overlaps the data's SM-parameter confidence region (from the data profile), via the chosen bridge. Consistent cmparamsets form the posterior over CM parameter space.

The CM-side profiles and CM parameters are row-aligned: uq_results[i] ↔ cm_sample.params[i, :] (mirroring SmoreGSA's runSensitivity). A raw matrix is accepted and wrapped with CMSample (from SmoreBase: grid if possible, else scattered).

Arguments — describing how to fit/profile the SM against the real data

  • problem::SMFitProblem — bundles sm, the real data (single param-set), the SM prior, and the loss to use when fitting and profiling the SM against that data
  • or sm::AbstractSurrogateModel + data::AbstractCMData — equivalent to passing a problem built internally as SMFitProblem(sm, data, uq_results[1].fit_result.prior; loss = loss)

Arguments — describing the CM param_sets already profiled upstream

  • uq_results::Vector{<:ProfileLikelihoodResult} — one profile likelihood result per CM paramset, computed upstream against that paramset's CM-generated data
  • cm_sample::AbstractCMSample (or cm_params::AbstractMatrix) — CM parameter locations, row-aligned with uq_results

Keyword Arguments

  • cm_names::Vector{String} — CM parameter names, for labeling the posterior; defaults to cm_sample.names (from SmoreBase's GridCMSample/ScatteredCMSample), or to CMSample's auto-generated "cm_1", ... when a raw cm_params matrix is supplied without names attached
  • bridge::Symbol = :box_overlap — overlap test: :box_overlap (box-vs-box overlap volume, scored per box_score), :data_trace_in_box (data profile trace points inside the CM box), or :symmetric_trace
  • box_score::Symbol = :jaccard — how :box_overlap scores the overlap of the CM box and the data box (ignored by the trace bridges):
    • :jaccard — overlap volume ÷ volume of the union of the two boxes (the Jaccard index). Symmetric, and 1 only for identical boxes, so a wide CM box (e.g. an open CI stretched to the edge of the prior range) is penalized for its width.
    • :data_normalized — overlap volume ÷ data-box volume (the default before v0.6). Not symmetric: a CM box that contains the data box scores 1.0 however large it is.
    Any other value throws ArgumentError.
  • profile_options::ProfileLikelihood = ProfileLikelihood() — settings for the data profile (the CM-side profiles in uq_results are already final and not recomputed); recorded as post.data_profiles.method
  • p0 = nothing — initial guess for the data fit ([1 × n_sm_params]); defaults to the column-mean of the CM param_sets' SM fits
  • loss::AbstractLoss = GaussianNLL() — loss for the data fit, only on the (sm, data, …) forms; the problem form uses problem.loss
  • gate::AbstractGate = NullGate() — the posterior's gate, chosen here once and stored as post.gate. A cmparamset that fails it counts as score 0 and is never accepted; IdentifiabilityMatchGate fails every cmparamset whose CI shape (bounded or open, per SM parameter and side) differs from the data's. post.scores keeps the bridge's scores and post.gate_pass records who passes; interior queries apply the same gate
  • min_score::Union{Real,Symbol} = 0.0 — a cmparamset is accepted iff it passes the gate and its score exceeds this; also the default threshold for inPosterior interior queries. :elbow sets it to τelbow, the elbowThreshold of the scores that pass the gate; the value used is stored as `post.minscore. Any other symbol throwsArgumentError`
  • interp::AbstractCIInterpolator = LinearCIInterp() — how the per-cmparamset SM-parameter CI bounds are interpolated across the CM grid for interior queries; only consulted when cm_sample isa GridCMSample (interior queries are not built for scattered layouts); stored as post.interp for every layout

Returns

CMPosteriorResult. Use posteriorSamples for accepted CM sets, posteriorWeights for a graded posterior, and acceptedGrid / scoreGrid for grid-shaped views.

Example

# If you already have an SMFitProblem for the real data in hand:
problem = SMFitProblem(sm, data, sm_prior)              # SM + real data + SM prior
post    = buildPosterior(problem, uq_results, cm_params; bridge = :box_overlap)

# Otherwise, pass sm and the real data directly:
post = buildPosterior(sm, data, uq_results, cm_params)

# Identifiability gate, then the elbow threshold on the scores that pass it:
post = buildPosterior(sm, data, uq_results, cm_params;
                      gate = IdentifiabilityMatchGate(), min_score = :elbow)

posteriorSamples(post)   # CM parameter vectors consistent with the data

SmoreFit.elbowThreshold — Method
elbowThreshold(scores) -> (tau, rank, n_positive, note)

The elbow threshold τelbow of a set of scores; accept a CM paramset when its score is > tau.

Sort the positive scores from highest to lowest, s[1] ≥ … ≥ s[n], and scale rank and score to [0, 1] (x = (rank − 1)/(n − 1), y = (s − s[n])/(s[1] − s[n])). Join the first and last points with a straight line; the elbow is the point farthest below that line, and τelbow is its score. The elbow point itself is therefore rejected, and because τelbow is a score value, CM param_sets with tied scores are accepted or rejected together.

If fewer than three scores are positive, or no point lies below the line (including when all positive scores are equal), τ_elbow is 0, which accepts every positive score.

Usually applied to the scores that pass the gate, post.scores[post.gate_pass]; buildPosterior(...; min_score = :elbow) does exactly that.

Returns

A named tuple:

  • tau — τ_elbow
  • rank — the elbow's rank among the sorted positive scores (0 when τ_elbow was set to 0)
  • n_positive — the number of positive scores
  • note — why τ_elbow was set to 0 ("" otherwise)

Example

e = elbowThreshold(post.scores[post.gate_pass])
accepted = post.gate_pass .& (post.scores .> e.tau)

SmoreFit.gateInterior — Method
SmoreFit.gateInterior(gate::AbstractGate, score, lb, ub, post::CMPosteriorResult) -> Float64

Gate the score of one interior CM point, whose SM-parameter box [lb, ub] was interpolated across the CM grid of post. Not exported. Called by posteriorScore with post.gate. Add a method for a new gate type to make interior queries work with it (see AbstractGate).

  • NullGate returns score.
  • IdentifiabilityMatchGate treats a side of the interpolated box as open when its bound is at (or beyond) the edge of the profile range and as bounded when it is strictly inside, and returns score if every side has the data's shape, else 0.0. The profile range is defined in the IdentifiabilityMatchGate docstring.

SmoreFit.openSides — Method
openSides(plr::ProfileLikelihoodResult) -> BitMatrix
openSides(lower, upper) -> BitMatrix

Which sides of each SM parameter's confidence interval are open, as [n_sm_params × 2]: row j is SM parameter j, column 1 its lower side, column 2 its upper side; true = open.

A side is open when the profile did not cross its threshold inside the prior range, which SmoreBase reports as a nothing bound (ProfileCurve.ci_lower / ci_upper). The second form takes the bounds directly, one entry per parameter; nothing and missing both count as open.

Example

uq = quantifyUncertainty(ProfileLikelihood(), problem, fit, 1)
open = openSides(uq)     # e.g. [false false; false true]: parameter 2 is open above
open[2, 2]               # is parameter 2 open on its upper side?
any(open)                # is any side open?
openSides([0.1, 5.0], [0.3, nothing])   # same answer from raw bounds

SmoreFit.posteriorScore — Method
posteriorScore(post::CMPosteriorResult, θ_cm::AbstractVector) -> Float64
posteriorScore(post::CMPosteriorResult, queries::AbstractMatrix) -> Vector{Float64}

Consistency score at one or more interior CM parameter points, using the same bridge (and, for :box_overlap, the same box_score) and the same gate (post.gate) that produced post; a point that fails the gate scores 0. The CM-side SM-parameter CI bounds are interpolated across the CM grid; the data-side profile (post.data_profiles) is unchanged.

queries[k, :] is the k-th query point; the vector form is one query.

Requires post.cm_sample isa GridCMSample and post.bridge in (:box_overlap, :data_trace_in_box).

Example

post = buildPosterior(sm, data, uq_results, cm_params)   # cm_params a regular grid
posteriorScore(post, [θ1, θ2])
posteriorScore(post, [θ1_a θ2_a; θ1_b θ2_b])   # batch
